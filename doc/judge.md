# 先判定要不要回

模板上一个开关「先判定要不要回」+ 一段判定提示词（`template.judge`）。开了的话，每条消息在 CC 起来**之前**先直接调一次模型 API（`judge.ts`），拿回 `{decision, reason}`。

## 为什么单独拆出来

以前这件事混在 CC 的系统提示词里（「不需要回就输出 SKIP」）：

- 标准写不具体，同类消息判得不一样；
- 判错的代价是开一张卡片 + 跑十几分钟全权限 CC；
- 不留理由，判错了说不清为什么。

拆出来之后：

- 判定有自己的提示词（分类 + 例子），CC 的提示词只管「怎么回」；
- 一次几秒、不带任何工具，判错了很便宜；
- 每次出一句理由，落库（`handled.reason`），web UI 上作业旁边看得到「为什么回 / 为什么没回」。

## 四种结论

| decision | 含义 | 做什么 |
|---|---|---|
| `answer` | 要回 | 交给 CC |
| `skip` | 不用回（闲聊、通知、MR 卡片、跟我无关） | 什么都不做，库里留理由 |
| `ask_me` | 只有我本人能答（排期、表态、私事，或没有可执行内容） | **私聊我一条**：谁、在哪、原话、为什么没替我回。群里什么都不发 |
| `stop` | 叫停（「别查了」「停止处理」） | 掐掉在跑的：对上追问锚点就只掐那个 session，对不上就掐这个会话里所有在跑的 |

判了不回的**不会**掐掉同一个 session 上在跑的：「谢谢」不该把正在查的打断。所以判定放在接棒之前。

## 输入和输出

输入是代码拼的，不是原始消息：会话类型（群 / 私聊）、发送人、@了谁（除了我还有谁）、**是不是追问**（对上了上一轮的 session）、消息正文（截到 2000 字）。

**输出格式写死在代码里**（`FORMAT`），不放进可编辑的提示词：改提示词的人弄不坏解析。

解析不用 `JSON.parse` 整个对象，而是按字段正则抠：模型可能包一层代码块、前面带几句话，理由里还常夹着没转义的引号（实测 136 条里 4 条），整体 parse 直接挂。

## 失败了怎么办

判定挂了（网络错误、认不出结论）**按要回处理**：多跑一次 CC 的代价，比悄悄吞掉别人的 @ 小。理由里会写「判定失败，按要回处理」。

## 打到哪

- **可选：Google Gemini Decisions API**（设置 → 常规里开启，`config.json` 顶层 `decisionApi`）：开启并填好 Google AI Studio API Key（或设环境变量 `GEMINI_API_KEY`）后，判定优先打 `POST /v1beta/decisions`（默认模型 `gemini-decision-1`）。单次请求并发评估 4 题（四选一分流 `choice` + 提示词注入检测 `noul` + 是否需查代码/日志 `noul` + 紧急度 4 档打分 `score`），共享输入、0 output tokens，不依赖 Anthropic 网关，纯 Claude 订阅和 Codex 模板也能用；多维结果和概率分布会落库并在后台详情卡里展示，遇到误判时可在后台直接点「手动回复到飞书」跳过判定补回。调用失败会自动回退到下面的 Anthropic 网关。注意：Google AI Studio 免费层的输入可能用于改进模型，涉密工作群建议用付费层或改走内网网关。
- **默认 / 回退：API 来源里的网关**（订阅的令牌只认 Claude Code，不能直接调 API，跳过），按顺序，一个失败换下一个，出过事歇着的排后面。模板固定了某个来源就只用它。一个网关都没有就跟 claude 用同一套：环境变量优先，其次 `~/.claude/settings.json` 的 `env`（`ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN` / `ANTHROPIC_API_KEY`）。见 `judgeTargets()`。
- 模型是这个网关 **haiku 那档**的名字（来源的 `models.haiku`；跟 claude 自己配置走时看 `ANTHROPIC_DEFAULT_HAIKU_MODEL`），都没有就是 `claude-haiku-4-5`（实测 p50 1.8 秒）。走网关时会先思考一轮的模型（自动路由那类）慢一倍。`max_tokens` 留到 1024，就是给先吐 thinking 的网关模型留余量。
- **一个都打不了**（没开 Google Decisions API，也只有订阅且 claude 自己没配令牌）：不白打一次 401，直接按要回，理由写「没有能判定的网关」。这种配置在模板的「先判定」开关底下、「实际会怎么跑」和向导里都标红。

## 不开判定

模板不填 `judge` = **直接回**：每条消息都交给 CC。自己用的模板一般就这样。

这时「要不要回」只剩 CC 自己的系统提示词兜着：CC 真吐了一个 `SKIP` 开头的回答，还是会被认出来、不发（`isSkip()`；`SKIP` 后面紧跟英文字母的不算，「SKIP LOCKED 是 PG 的行锁选项…」是正经回答）。系统提示词留空的话就没有这条规则了，见 [config.md](config.md#系统提示词留空就是空)。

## 调提示词

- 模板页有「填入内置默认」：`DEFAULT_JUDGE_PROMPT`，一个可以直接改的起点，不是运行时的兜底。
- 试跑框里有「只看判定」，改提示词时不用真跑 CC。
- 拿历史 136 条跑过：判定跟当初 CC 自己的选择对得上的约 73%。对不上的大多是**没带上下文的追问**（「把它乘以 7」）：跑历史时拿不到话题信息，实际运行时会标成追问，提示词里追问默认 `answer`。
