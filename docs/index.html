01 TWO ENTRYPOINTS

两个入口，共用模板库，可以都开也可以只开一个

想要零侵入、不用把机器人拉进群，就用 @我；想要秒级推送和打字机流式体验，就打开 @机器人。两条路同时开着时，同一条消息同时 @ 了你和机器人，只会由机器人回一次。

@我 默认开启
零侵入 · 免拉机器人

全程以你本人的飞书身份（--as user）搜索并回复，群里不需要加机器人，也不需要任何 Tenant Bot 权限。适合桌面版开箱即用。

  • 触发方式群里或私聊里有人 @你本人（不 @ 的私聊不会误触发）
  • 回复身份你本人（卡片直接显示成你发在原消息的话题下）
  • 响应速度分钟级（受飞书搜索索引延迟影响，约 1–2 分钟）
  • 流式更新确认要答复后才开话题，每 1.2 秒整张卡片原地刷新
  • 默认策略所有群默认关闭，在控制台左栏逐个打开白名单
@机器人 可选开启
秒级 · CardKit 流式

通过飞书事件长连接实时接收消息，一收到就发卡片并打字机流式输出。默认关闭，建议先将机器人默认模板设为只读后再启用。

  • 触发方式群里 @机器人，或者直接私聊机器人（不用 @）
  • 回复身份机器人身份发卡（读话题上下文与私聊通知仍借你本人身份）
  • 响应速度秒级（im.message.receive_v1 长连接推送）
  • 流式更新飞书 CardKit 原生打字机效果，无 CardKit 权限自动降级
  • 防重设计独立 bot.db 锚点存储；同时 @本人与机器人时自动由它接管
02 CAPABILITIES

为真实团队协作打磨的每一处细节

不是简单的消息转发器，而是围绕「可信、可控、可追问、可审计」构建的本地 Agent 路由器。

双引擎：Claude Code & Codex

每个模板可独立指定执行器、模型档位（opus / sonnet / haiku）与权限级别。支持配置多个 API 来源（公司网关 + 个人订阅），遇限流或额度耗尽自动切下一个续跑。

Claude Code Codex CLI API 自动容灾

智能「先判定」，不刷群

模板开启判定后，消息先走一次轻量无工具判定：闲聊和通知直接静默跳过，需要你本人拍板的事私聊转交给你，说「不用查了」立即掐停正在跑的任务。

03 LIFECYCLE

一次应答的完整生命周期

单进程 Node 24 架构（原生 TypeScript + node:sqlite），无外部数据库、无消息队列、无云端中转。

01

收到 @ 消息

@我 轮询搜索或 @机器人 长连接推送，过滤未开自动回会话与非真人消息。

02

SQLite 去重认领

INSERT OR IGNORE 原子去重，跨通道同时 @ 时只由机器人接管。

03

先判定分流

可选轻量判定输出 answer / skip / ask_me / stop，闲聊不留痕。

04

锚点续 Session

匹配话题或引用卡片锚点，拉取上下文与截图；旧轮次未完自动中断接棒。

05

本机代理执行

进程内并发闸调度本机 Claude Code / Codex，在目标工作区流式调用工具。

06

双路实时输出

边跑边写飞书流式卡片（30KB 预算自适应），同时通过 SSE 直播到控制台。

04 REAL OUTPUT

卡片发成功才算完成，控制台里所见即所得

控制台里的「卡片」标签页直接复用真实的飞书卡片渲染代码。任务跑完后结论全文直接呈现，过程按需折叠；如果网络波动导致卡片没发出去，点一下「重发到飞书」即可补发，无需重跑模型。

  • ✓ 安全试跑：输入问题选好会话，真跑一次代理，卡片以你身份只发给你自己，不进群、不污染去重库。
  • ✓ 优雅停机：Ctrl+C 或退出应用时自动把在跑的卡片收尾成「⚠️ 已中断」，意外崩溃下次启动自动补齐。
  • ✓ 环境健康告警：某个 MCP 掉线或插件授权过期时，主动私聊提醒你，不再默默少工具。

# 0. 前置要求：Node ≥ 24、已安装 lark-cli、已登录 Claude Code 或 Codex CLI
git clone https://github.com/zhengziyi0117/lark-cc-router.git
cd lark-cc-router
npm i

# 1. 以本人身份扫码授权飞书最小权限集（@我 入口无需任何 bot 权限）
lark-cli auth login --scope "search:message im:message.group_msg:get_as_user im:message.p2p_msg:get_as_user im:message:readonly im:message.send_as_user im:message im:chat:read im:message.reactions:read"

# 2. 生成配置并启动控制台
cp config.example.json config.json
npm start

启动后打开 http://127.0.0.1:8787，在模板里填好本地项目路径，然后在左栏选中会话打开「自动回」。详细飞书应用建权与 @机器人 配置请查阅 README 权限指南。

06 HONEST SCOPE

适合什么场景，以及它刻意不是什么

把边界说清楚，用起来才踏实。

适合 这些日常协作场景

  • 同事问代码实现与业务口径：不用打断手头深度工作，把只读模板挂在项目群里随时查仓库、翻文档、解释接口与配置。
  • 查数据、查日志、调本机 MCP 工具：把你本机已经接好的数据库、监控、文档工具一并复用，查了什么、结论是什么，群里一目了然。
  • 暂时离开电脑或值班被 @ 时：问题不急但希望先有第一轮定位，回来时话题里已经有结构化结论。
  • 复杂问题持续追问：在原话题继续 @ 或引用卡片追问，直接续上同一个对话上下文，不用从头说起。

不是 这些容易踩坑的定位

  • 不是爱插嘴的聊天机器人：开了「先判定」后，闲聊、通知、MR 卡片直接跳过，群里不留一丝噪音；需要你表态的事私聊转给你。
  • 不是对所有群放开的全权限代理：未开「自动回」绝不响应，权限按模板精细分级，面向他人的模板建议固定使用只读 plan 模式。
  • @我 路线不是秒回：依赖飞书搜索索引，延迟约 1–2 分钟；如果你需要秒级打字机回复，请开启 @机器人 入口。
  • 卡片输出无人工确认闸门：一旦开卡即实时写进群里，请留意本地仓库与工具所能触达的数据范围。
