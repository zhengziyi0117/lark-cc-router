两个入口，共用同一套模板库

想零侵入、不用把机器人拉进群，默认用 @我；需要长连接秒级响应与打字机流式输出，再按需打开 @机器人。同一条消息同时 @ 了你和机器人时，只会由机器人回复一次。

@我

默认开启，桌面版主推

全程以你本人的飞书身份搜索并回复，无需把机器人拉进群，也不需要任何 Bot 权限。

触发条件
群聊或私聊中有人 @你本人，未 @ 的私聊不会误触发
回复身份
你本人，卡片直接挂在原消息的话题下面
响应速度
分钟级，受飞书搜索索引延迟影响，约 1 至 2 分钟
卡片刷新
判定需要答复后才建话题，每 1.2 秒整张原地更新
默认范围
所有会话默认关闭，在控制台左栏逐个打开自动回

@机器人

为真实团队协作打磨的细节

不是把消息原样扔给大模型的转发器，而是围绕可控、可追问、可审计构建的本地代理路由器。

双引擎与多来源容灾

每个模板可独立指定 Claude Code 或 Codex CLI、模型档位与权限模式。配置多个 API 来源（公司网关与个人订阅）后，遇限流或额度耗尽自动切换下一个继续完成。

先判定再回复，群里零噪音

开启判定后，消息先经过一次无工具轻量判断，分流为要回、不用回、转给我或叫停。闲聊和公告静默跳过不留痕迹，需要你拍板的事私聊转交给你。

原话题续问与截图上下文

在卡片所在话题继续 @，或私聊引用卡片追问，自动续上同一个本地 Session。话题历史与消息里的截图会一并交给代理；上一轮未结束时，新追问自动中断旧轮次接棒。

按对话聚合的本机控制台

打开 127.0.0.1:8787 实时查看思考、工具入参与耗时时间轴，重启后依然能从记录找回完整对话并直接接着问。内置试跑与只看判定，卡片只发给自己不进群。

开箱即用的桌面端与本机同步

提供 macOS Apple Silicon 与 Windows 安装包，向导式引导配置，关窗退到菜单栏或系统托盘常驻并后台静默更新。一键从 ~/.claude 同步本机 MCP、插件与 Skills。

清晰且坦诚的安全边界

未开自动回的会话绝不响应，新建模板默认只读 plan 模式。控制台仅监听回环地址并防跨站与 DNS Rebinding，配置文件保持 0600 权限且密钥绝不下发前端。

从一条 @ 到一张卡片的六步闭环

单进程 Node 24 架构，原生运行 TypeScript 与 node:sqlite，不依赖外部数据库或云端中转。点击下方任意步骤查看每一步的职责与模块。

卡片发成功才算完成，控制台所见即所得

控制台里的卡片预览直接复用真实的飞书卡片渲染代码。任务结束后结论全文直接展开，排查过程收进折叠区；如果网络波动导致收尾帧没改上，点击「重发到飞书」即可补发，不用重跑模型。

  • 安全试跑：输入问题并选好目标会话，卡片以你的身份只发给你自己，不进群、不写入去重库。
  • 优雅停机：退出应用时自动将在跑的卡片收尾为「已中断」，意外崩溃下次启动自动补齐。
  • 环境健康告警：本机某个 MCP 掉线或插件授权过期时，主动私聊提醒你，不再默默缺少工具。

Node ≥ 24 · lark-cli · Claude Code 或 Codex CLI 
# 1. 克隆仓库并安装依赖
git clone https://github.com/zhengziyi0117/lark-cc-router.git
cd lark-cc-router
npm i

# 2. 以本人身份扫码授权飞书最小权限集（@我 入口无需任何 bot 权限）
lark-cli auth login --scope "search:message im:message.group_msg:get_as_user im:message.p2p_msg:get_as_user im:message:readonly im:message.send_as_user im:message im:chat:read im:message.reactions:read"

# 3. 生成配置并启动本机控制台
cp config.example.json config.json
npm start

启动后访问 http://127.0.0.1:8787，在模板里配置本地项目目录，然后在左栏选中会话打开「自动回」。完整飞书应用建权与 @机器人 长连接配置请查阅 README 权限指南。

它擅长什么，以及它刻意不做哪些事

把能力边界写明白，放进工作群里才用得踏实。

适合的日常协作

  • 解答代码实现与业务口径：把只读模板挂在项目群里，同事问接口、配置或逻辑时不必打断你手头的深度工作。
  • 查数据、翻日志与联动 MCP：直接复用本机已接好的监控、文档和查询工具，查了什么、结论是什么，群里所有人一目了然。
  • 离开电脑或值班被 @ 时：问题不急但希望先完成第一轮信息收集与定位，回来时话题里已经有清晰结论。
  • 复杂问题持续追问：在原话题继续 @ 或引用卡片追问，直接续上同一轮上下文，不用从头描述背景。

刻意划清的边界

  • 不是爱插嘴的聊天机器人：开启「先判定」后，闲聊、通知与 MR 卡片直接静默跳过，需要你本人表态的问题私聊转交给你。
  • 不是全群放开的全权限代理：未打开「自动回」的会话绝不响应，权限按模板分级，面向他人的模板建议固定为只读 plan 模式。
  • @我 路线并非秒回：受飞书搜索索引影响延迟约 1 至 2 分钟，需要秒级打字机流式回复请启用 @机器人。
  • 卡片输出没有人工确认闸门：一旦开卡即边跑边写进群里，请留意目标仓库与本地工具可触达的数据范围。
