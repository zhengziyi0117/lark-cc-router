# 先判定要不要回

模板上一个开关「先判定要不要回」+ 一段判定提示词（`template.judge`）。开了的话，每条消息在 CC 起来**之前**先直接调一次模型 API（`judge.ts`），拿回 `{decision, reason}`。

## 为什么单独拆出来

以前这件事混在 CC 的系统提示词里（「不需要回就输出 SKIP」）：

- 标准写不具体，同类消息判得不一样；
- 判错的代价是开一张卡片 + 跑十几分钟全权限 CC；
- 不留理由，判错了说不清为什么。

拆出来之后：

- 判定有自己的提示词（分类 + 例子），CC 的提示词只管「怎么回」；
- 一次几秒、不带任何工具，判错了很便宜；
- 每次出一句理由，落库（`handled.reason`），web UI 上作业旁边看得到「为什么回 / 为什么没回」。

## 四种结论

| decision | 含义 | 做什么 |
|---|---|---|
| `answer` | 要回 | 交给 CC |
| `skip` | 不用回（闲聊、通知、MR 卡片、跟我无关） | 什么都不做，库里留理由 |
| `ask_me` | 只有我本人能答（排期、表态、私事，或没有可执行内容） | **私聊我一条**：谁、在哪、原话、为什么没替我回。群里什么都不发 |
| `stop` | 叫停（「别查了」「停止处理」） | 掐掉在跑的：对上追问锚点就只掐那个 session，对不上就掐这个会话里所有在跑的 |

判了不回的**不会**掐掉同一个 session 上在跑的：「谢谢」不该把正在查的打断。所以判定放在接棒之前。

## 输入和输出

输入是代码拼的，不是原始消息：会话类型（群 / 私聊）、发送人、@了谁（除了我还有谁）、**是不是追问**（对上了上一轮的 session）、消息正文（截到 2000 字）。

**输出格式写死在代码里**（`FORMAT`），不放进可编辑的提示词：改提示词的人弄不坏解析。

解析不用 `JSON.parse` 整个对象，而是按字段正则抠：模型可能包一层代码块、前面带几句话，理由里还常夹着没转义的引号（实测 136 条里 4 条），整体 parse 直接挂。

## 失败了怎么办

判定挂了（网络错误、认不出结论）**按要回处理**：多跑一次 CC 的代价，比悄悄吞掉别人的 @ 小。理由里会写「判定失败，按要回处理」。

## 打到哪

- 模型是服务级的 `judgeModel`（默认 `claude-haiku-4-5`，实测 p50 1.8 秒）。走网关时会先思考一轮的模型（自动路由那类）慢一倍。`max_tokens` 留到 1024，就是给先吐 thinking 的网关模型留余量。
- 地址和凭证跟着**模板的网关**走；模板没配就用顶层 `gateway`；再没有就跟 claude 用同一套：环境变量优先，其次 `~/.claude/settings.json` 的 `env`（`ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN` / `ANTHROPIC_API_KEY`）。
- web UI 模板设置里的「测一下」就是拿 `judgeModel` 往网关发一个最小请求。

## 不开判定

模板不填 `judge` = **直接回**：每条消息都交给 CC。自己用的模板一般就这样。

这时「要不要回」只剩 CC 自己的系统提示词兜着：CC 真吐了一个 `SKIP` 开头的回答，还是会被认出来、不发（`isSkip()`；`SKIP` 后面紧跟英文字母的不算，「SKIP LOCKED 是 PG 的行锁选项…」是正经回答）。系统提示词留空的话就没有这条规则了，见 [config.md](config.md#系统提示词留空就是空)。

## 调提示词

- 模板页有「填入内置默认」：`DEFAULT_JUDGE_PROMPT`，一个可以直接改的起点，不是运行时的兜底。
- 试跑框里有「只看判定」，改提示词时不用真跑 CC。
- 拿历史 136 条跑过：判定跟当初 CC 自己的选择对得上的约 73%。对不上的大多是**没带上下文的追问**（「把它乘以 7」）：跑历史时拿不到话题信息，实际运行时会标成追问，提示词里追问默认 `answer`。
